## Д. Сервер и кабинеты

**Д1. Когда и нужен ли** 🔶. Облачный сервер до ≈ 15 $ в месяц (Claude собирает всё, вы один раз ставите по инструкции) — решено **в принципе**, но **откладывается до первых денег**. Или платная услуга «кабинет учителя» школам.

**Д2. Страна хостинга** 🔶. По закону о персональных данных Узбекистана (насколько известно Claude, не проверено юристом) данные граждан, возможно, нужно хранить на серверах в стране — проверить до выбора провайдера. Домашний компьютер как сервер — только для пилота и с мерами безопасности (`docs/plans/pilot.md`).

**Д3. Кто обслуживает** ⏳. Вы сами (по пошаговой инструкции Claude) или найти человека; резервные копии, обновления, наблюдение.

**Д4. Сервер на старом ноутбуке (Toshiba) вместо аренды** 🔶 (мысль владельца 20.11.2026: аренда дорога, а когда заплатит школа — неизвестно). Оценка Claude: для пилота **разумно и бесплатно**, если сделать безопасно — отдельный ноутбук только под сервер (лучше Linux, шифрование диска), доступ из интернета через туннель без открытия портов роутера, только HTTPS, резервные копии на внешний диск и зашифрованная копия вне дома, автообновления; батарея ноутбука — встроенный «бесперебойник»; следить за нагревом (не на мягком, не под одеялом), проверить состояние батареи и диска. Минусы: доступность зависит от света и интернета, домашний канал, нагрузка в сотни одновременных учеников может не потянуться. Данные физически в Узбекистане (может помочь с вопросом закона о персональных данных — не заключение юриста). Сервер нужен только когда написаны кабинеты; для пилота на открытом сайте без сервера он не нужен. Сервер пишется так, чтобы переезд на арендованный занимал час. **Ждёт решения владельца; нужно знать:** модель, оперативную память, SSD или HDD, состояние батареи, провайдера и скорость отдачи.

**Д5. Данные в приватном репозитории GitHub** (мысль владельца 20.11.2026; оценка Claude, ждёт решения). **Для данных учеников — не стоит:** сайт не может безопасно писать в приватный репозиторий (токен в коде страницы виден всем, нужен посредник-сервер); git плохо переносит одновременные записи и лимиты запросов; история хранится вечно — удалить данные ученика по просьбе сложно (решение 14, «Удаление»); персональные данные детей на зарубежных серверах (вопрос закона Узбекистана); доступ участников и ИИ-агентов репозитория к данным; блокировка или взлом аккаунта GitHub затронет данные. **Для закрытого содержания — подходит:** ответы (`key`) вынести в отдельный приватный репозиторий (связано с А3; цена — `tools/build.py` должен читать второй репозиторий), рабочие материалы, зашифрованные резервные копии. Пока данные учеников остаются на устройстве (`localStorage`) с копией файлом.
