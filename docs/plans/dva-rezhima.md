# Два режима: «Справочник» (самостоятельное изучение) и «Курс» (по шагам)

**Слово владельца 27.11.2026** (после разбора интерфейса, `docs/audit/ux-analiz-2026-11-27.md`): учебник — это **библиотека**, скорее для самостоятельного изучения, чем курс; но и как курс его надо проработать — **отдельным режимом, может быть, отдельной ссылкой и сайтом на GitHub**. Статус: направление принято, детали — 🔶 ждут решения (раздел «Открытые вопросы»).

## Как разошлись найденные проблемы
| Проблема из разбора | Кого касается |
|---|---|
| 1. Нет «урока» как единицы, ленты 26 000 / 54 000 px | **Курс** |
| 2. Много входов, два «следующих шага» на главной | оба (в справочнике — лишнее, в курсе — вредное) |
| 3. Шапка главы съедает экран, непонятные «Проще/Углублённо» | **Курс** (в справочнике — свернуть) |
| 4. Тренажёр с анкеты, задание не по уроку | **Курс** |
| 5. Упражнения «в тетрадь» без ввода | оба (в курсе — с ответом на экране) |
| 6. Четыре «словаря» | **Справочник** |
| 7. Цифры про книгу, а не про ученика | **Курс** |
| 8. Шум пунктира, стена определений | **Справочник** |

То есть большая часть «неудобства» — это **курсовые ожидания, предъявленные к справочнику**. Разделение снимает конфликт, а не просто переименовывает кнопки.

## «Справочник» (то, что есть сейчас, облегчённое)
- Назначение: найти правило за 20 секунд, прочитать главу целиком, свериться.
- Вход — **поиск** (единый: главы, уроки, термины, слова, правила); «Содержание» и «Глоссарий/Словарь/Словарик» сливаются в один раздел **«Справочник»**.
- Глава остаётся целиком (лента допустима: это режим чтения), но шапка короче; режимы «Проще»/«Углублённо» — одним переключателем «Объяснение: обычное · проще · глубже».
- Без маршрута, серий, счётчиков готовности; прогресс — необязательный (что читал).

## «Курс» (новое)
- Назначение: вести ученика по линейному маршруту (14 ступеней, 51 глава) без выбора и без анкет.
- **Урок — единица:** экран урока = короткая порция теории (в данных уже есть уроки и `lite`) → «Потренироваться» (5–8 заданий именно этого урока) → «Проверить себя» (тест урока) → «Дальше»; сверху «Урок 3 из 6 · Глава 1.1».
- **Одна главная кнопка** «Продолжить»; всё остальное — второстепенно; главная содержит только: что дальше, прогресс ученика («Урок 12 из 310», минуты сегодня), серия.
- Тренажёр курса — **без настроек**: задания по текущему уроку, от лёгкого к сложному; настройки — за значком.
- Уровни освоения урока: «знакомо → уверенно → освоено» с публичными правилами (по результатам заданий и теста; как у Khan Academy).
- Упражнения «в тетрадь» в курсе — с полем «записал» и открытием образца/ответа на экране (ответы в версии ученика по-прежнему не выкладываются, решение 15 — для курса нужны **самопроверка по образцу** и проверка учителем).
- Для учителя: «Собрать задание» (урок + число заданий → ссылка), «Отправить учителю» (ученик создаёт файл/ссылку результата), страница учителя с загрузкой нескольких файлов (без сервера, решение 20.11).

## Техника: как разделить на GitHub
Варианты:
1. **Одна кодовая база, два входа на одном сайте (рекомендация).** `https://<пользователь>.github.io/<репо>/` — Справочник; `…/kurs/` — Курс. Сборка даёт два файла (`_site/index.html`, `_site/kurs/index.html`; `pages.yml` уже копирует один файл в `_site`, добавить второй — одна строка). **Один origin → общий `localStorage`**, поэтому прогресс и профиль общие; ссылки на упражнения (`#ex-…`) работают в обоих.
2. **Отдельный репозиторий и сайт для курса.** Отдельный origin → прогресс не общий, содержание дублируется или тянется второй сборкой; двойное обслуживание. Оправдано, только если курс захотят отдать другому владельцу/школе или лицензировать отдельно.
3. **Один сайт, один файл, режим внутри** (как сейчас + переключатель). Самый дешёвый, но воспроизводит нынешний конфликт («две навигации»).

**Вес.** Сейчас `index.html` ≈ 27 МБ (всё содержание в файле). Два файла по 27 МБ — расточительно; правильнее выделить **данные в общий файл** (`data.js`), а оболочки Справочника и Курса сделать лёгкими. Это совпадает с решением 20.11 «постепенная загрузка» — делать вместе.

## Порядок работы (предложение)
1. Решить открытые вопросы (ниже).
2. Выделить данные от оболочки (`tools/build.py`: общий `data.js`, оболочки `index` и `kurs`) — без изменения поведения; тесты зелёные.
3. Оболочка «Курс»: главная с одной кнопкой → экран урока (теория урока + «Потренироваться» + «Проверить себя» + «Дальше») → уровни освоения.
4. Оболочка «Справочник»: единый поиск, слияние словарей, укороченная шапка.
5. Проверка на 3–5 реальных учениках (по 10 минут, «найди и сделай домашку по теме X»).
