# Пилот в школе владельца (решение владельца 18.11.2026)

Запись разговора 18.11.2026 (чат) — чтобы новый чат продолжил без вопросов.

## Решения владельца

1. **Бесплатный пилот на месяц** в частной школе, где работает владелец. Учебник дают в пользование всей школе (ученикам и учителям); цель — отзывы, поиск ошибок, цифры для разговора об оплате. Уже тестировали на учениках, когда было три готовые главы.
2. **Не ждать конца.** Пилот начинается, когда дописаны оставшиеся главы маршрута (расчёт — ниже); новые правки идут в пилотную версию по расписанию, а не после каждого слияния.
3. **Версии разделены.** Для ученика (сайт и Android, без ответов — решение 15) и для учителя (с ответами, отдельным файлом) — разные адреса и разная выдача. Нужно заранее, чтобы **GitHub не «упал» от сотен запросов** (ниже — меры).
4. **После пилота — платная модель «лицензия школе»** (платит администрация); ученикам доступ бесплатный. Цена и условия — **ждут решения владельца** (ориентир Claude, не решение: ступени по числу учеников — до 300 учеников ≈ 3–4 млн сум в год, 300–800 ≈ 6–8 млн, 800 и больше ≈ 10–14 млн; частным школам можно выше). Основа продажи — кабинет учителя и статистика (этапы B–C `ROADMAP.md`): до готового сервера продавать пилот, а не годовую лицензию.

5. **Учебник принадлежит владельцу и уходит вместе с ним** (слово владельца 18.11.2026, позже в тот же день): **никому не раздавать APK, текстовую, печатную и офлайн-версии, файл учителя.** Школа получает только **доступ онлайн, который владелец может отозвать** (закончился пилот, ушёл из школы, не заплатили — доступ закрыт, копий у школы нет). Это **отменяет** пункты 2–4 мер ниже (APK, раздача файла учителям, кэш для работы без сети) и требует закрытой выдачи вместо публичной GitHub Pages — см. «Закрытая выдача».

6. **Порядок работ (слово владельца 18.11.2026): сначала доделываем все главы (3–4 ночи), потом серверная часть с кабинетами** (этапы B–D `ROADMAP.md`: закрытая выдача, вход по коду, кабинет учителя, журнал, статистика). **Пилот в школе начинается после серверной части**, а не раньше; срок серверной части — оценить отдельно, когда главы будут готовы (дни работы, не ночи). Пока работает только ночная очередь глав (`NIGHT-QUEUE.md`, раздел Ж).

## Закрытая выдача (предложение Claude 18.11.2026 — ждёт решения владельца)

Что не получится при любой схеме: если страницу видно на экране, её можно сфотографировать, переписать, сохранить из браузера — «абсолютной» защиты нет (как с книгой). Реально достижимое: **закрыть вход, не отдавать файл целиком, уметь отозвать доступ и узнать, откуда утечка**, плюс договор.

1. **Вход по коду/паролю школы**, срок действия и отзыв на стороне сервера. Публичная GitHub Pages для пилота не годится: сайт виден всем, и 18,9 МБ файл можно скачать одним сохранением.
2. **Содержание — по главам, с сервера, после проверки доступа** (а не одним файлом в браузере). Это же снимает нагрузку: ученик получает только открытую главу.
3. **Сервис-воркер и «офлайн» — нет** (кэш = копия на устройстве); если нужна работа при плохой связи — кэш только на время сеанса и с проверкой срока лицензии при запуске.
4. **Версия учителя (с ответами)** — только за отдельным входом на сервере; файлом не раздавать.
5. **Метка утечки:** у каждого кода доступа — своя невидимая метка в страницах, чтобы по найденной копии понять, откуда она.
6. **Договор — лицензия, а не продажа:** авторские права остаются у владельца, школе — право пользоваться в срок; запрет копирования, передачи и раздачи; отзыв доступа по окончании. **Юрист:** (а) оформление договора; (б) вопрос, не считается ли учебник произведением, созданным по заданию работодателя, раз владелец работает в этой школе (в Узбекистане — по закону об авторском праве; Claude не юрист) — зафиксировать письменно, что учебник создан вне служебных обязанностей и принадлежит владельцу.
7. **Хостинг** — свой небольшой сервер (VPS) или сервис с проверкой доступа (например, Cloudflare Workers/Access); подбор — с владельцем. Репозиторий на GitHub — **приватный**, если ещё нет (проверить: содержание всех глав видно в исходниках).
8. Связь с ROADMAP: это то же, что «сервер учителя» (этапы B–D), только в минимальном виде и раньше срока; «данные только у учителя» и «защита данных» (решение 14) сохраняются.

## Нагрузка на GitHub — меры (⚠ пункты 2–4 отменены решением 5; остаётся 1, 5, 6 и «Закрытая выдача»)

Замер 18.11.2026: `dist/index.html` — **18,9 МБ (≈ 4,3 МБ по сети со сжатием)**, версия учителя — 22,9 МБ. Пока нет сервиса-воркера, каждое обновление сайта заставляет **каждое устройство скачать весь файл заново**. Лимиты GitHub Pages — по документации GitHub (проверить актуальные перед запуском): сайт до 1 ГБ, мягкий предел трафика ≈ 100 ГБ в месяц, мягкий предел сборок ≈ 10 в час; Pages не предназначены для коммерческой деятельности и платных сервисов.

Расчёт: 300 учеников × 4,3 МБ × 30 обновлений в месяц ≈ 39 ГБ — запас есть, но только если не обновлять каждую ночь и школа не вырастет в разы.

1. **Замороженная пилотная версия.** Пилот — отдельный адрес (отдельная ветка или тег, отдельная публикация), обновляется по расписанию (например, раз в неделю в пятницу), а не после каждого слияния в `main`. Разработка в `main` идёт как раньше.
2. **Сервис-воркер и «установить на экран»**: после первого открытия учебник работает из кэша, скачивание — только при выходе новой пилотной версии. Сейчас сервис-воркера нет — **сделать до пилота**.
3. **Android-APK** — ставится один раз, трафика после установки нет; раздать файлом (мессенджер, флешка), сборка — `android.yml`.
4. **Версия учителя — не на сайте**, а файлом из запуска Actions (`uchebnik-dlya-uchitelya`, решение 15), раздаётся учителям напрямую; ответов в ученической выдаче нет.
5. **Если школа вырастет или пилот станет платным:** вынести выдачу с GitHub Pages на хостинг статики без жёстких лимитов трафика и с разрешённой коммерцией (варианты — Cloudflare Pages, Netlify, свой сервер; выбор и аккаунт — за владельцем) и/или разбить учебник на файлы по главам (подгрузка по требованию). Сейчас не делаем.
6. **Следить за трафиком:** смотреть статистику Pages/Actions раз в неделю; признак опасности — письмо от GitHub о лимитах.
